# Methods and literature

## Pipeline

Official Parquet → schema check → overlapping raw quality counts → conservative filtering → Parquet-backed DuckDB trip view → zone-hour and daily directed OD aggregates → chronological one-hour forecast → FastAPI → React visual analytics. The cleaned table is also exported as Parquet. Database and aggregation timings are observed wall-clock measurements on the local machine, not speedup claims. JSON results and hashes are generated by the same pipeline.

Required values must be present. Pickup must fall within January–March 2025; dropoff must be later and within four hours; distance must be greater than zero and at most 100 miles; both zone IDs must be valid non-unknown lookup entries. Rules overlap and their independent counts must not be added. These cutoffs are operational plausibility filters, not determinations that every excluded row is false. Exact duplicates are all-field matches within the three files; they are counted but retained because no unique trip identifier proves a duplicate. No broad statistical outlier trimming is performed. Timestamps are treated as source local wall time, without an explicit timezone or daylight-saving disambiguation.

The model predicts total cleaned pickup counts one hour ahead using actual lag 1, 24 and 168 hours, the mean of the 24 preceding hours, hour and day of week. Training ends in February; March is held out. At every test hour the previous observed counts are assumed available, so this is rolling one-step evaluation, not a month-ahead forecast. Seasonal naive uses the count 168 hours earlier. The first week supplies lag history. Missing entire hours are filled with zero; DST wall-clock timestamps make this an imperfect assumption. HistGradientBoostingRegressor uses fixed hyperparameters and seed; no test tuning. MAE and RMSE compare against actual demand. Forecast errors measure observed prediction performance, not causal effects or uncertainty intervals.

The hotspot module clusters zone-specific 24-hour demand proportions with deterministic K-means. It identifies relative temporal profiles and their geography, not statistically significant spatial hotspots. The method is sensitive to number of clusters, the selected window, low counts, unequal zone sizes and non-independent observations. Absolute volumes remain available in the atlas. OD flows are directed and are based on the same cleaned trips; the API returns the top 30 pairs after optional origin filtering. Scenario values are arithmetic counterfactual illustrations without a behavioural model.

## Selected literature and connection

1. NYC TLC, [trip record data](https://www.nyc.gov/site/tlc/about/tlc-trip-record-data.page) and [data dictionary](https://www.nyc.gov/assets/tlc/downloads/pdf/data_dictionary_trip_records_yellow.pdf): source provenance and definitions.
2. Safikhani et al., [Spatio-temporal modeling of yellow taxi demands](https://arxiv.org/abs/1711.10090): motivates considering spatial and temporal structure and out-of-sample evaluation; this project implements a simpler citywide temporal baseline and model, not their STAR model.
3. [Spatiotemporal Analysis of Ridesourcing and Taxi Demand by Taxi zones in New York City](https://arxiv.org/abs/2008.00568): supports zone-level temporal comparison; this project does not reproduce its multi-service analysis.
4. [Forecasting Taxi Demands with Fully Convolutional Networks and Temporal Guided Embedding](https://openreview.net/pdf?id=BygF00DuiX): illustrates deep spatiotemporal forecasting as a research alternative, not implemented here.
5. DuckDB, [Parquet documentation](https://duckdb.org/docs/stable/data/parquet/overview): supports compressed columnar scans and SQL analytics.
6. scikit-learn, [time series cross-validation](https://scikit-learn.org/stable/modules/cross_validation.html#time-series-split): motivates preserving time order; the project uses one held-out chronological period, not cross-validation.
7. scikit-learn, [clustering documentation](https://scikit-learn.org/stable/modules/clustering.html#k-means): informs K-means profile clustering and its assumptions.
